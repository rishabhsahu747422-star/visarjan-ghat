| D-14 | "Latest year" = latest year in dataset for that festival, not per-ghat | Bairagarh / Malikhedi Durga → Low confidence because 2025 is missing dataset-wide. | Final |
| D-15 | `recovery: good` means "no worse than before immersion", not "within limits". API adds `after_severity` (0 = within limits) and `latest_data_year` to each ranked ghat | Bairagarh 2024 had BOD 8.2 mg/l a week after immersion against a limit of 3 and still reads "good". The UI must not call it clean. UI wording: good = "No worse than before immersion", poor = "Worse a week later". | Final |
| D-16 | `test_priority` = risk_score × data-gap factor (confidence High 1.0, Medium 1.5, Low 2.0); null if risk is null | Points extra testing where risk is high and data is thin. Ranking order still uses risk_score only. | Final |
| D-17 | Brief quotes, per top ghat, the worst DO / BOD / pH reading across all years (ties go to the latest year); readings within limits are not listed; BDL says "below detection", missing says "not measured" | Keeps the headline reading (Bairagarh DO 0, 2023) in the brief and never lists an in-limit value as a problem. | Final |
| D-18 | Brief is capped at 150 words per language including the footer; when over, the template drops detail in a fixed order (confidence reasons, then the thin-data line, then quadrant/recovery phrases), same level for both languages. Top 3 ghats and no-data sites are never dropped | Meets the word cap without hiding a ghat or a data gap. | Final |
| D-19 | Quadrant `stable` is phrased "No clear rise during immersion", never "within limits"; recovery `good` is "Back to pre level after" | `stable` ghats can still breach limits (Malikhedi Ganesh BOD 16.8); D-11 "good" only means after ≈ pre. | Final |
| D-20 | Brief LLM is an open-weight model on Groq (`openai/gpt-oss-120b` by default, `GROQ_MODEL` to change, `LLM_PROVIDER=groq`) instead of Cerebras or Claude | Free tier, open weights. The LLM only rephrases; the validator and template fallback are unchanged, and `LLM_PROVIDER=none` stays the demo default. | Final |
| D-21 | Brief recovery wording: `good` is split into `good_above_limits` ("Still above limits after.") and `good_within_limits` ("Within limits after.") using `after_severity`; never "back to pre level" or "recovered" | Supersedes the "Back to pre level after" phrase in D-19. Without it the brief read as if a ghat recovered when Bairagarh Durga after-phase BOD was still above the limit (D-15). | Final |
| D-22 | Brief carries one action line per top ghat, chosen from computed values only: confidence below High → "Add a test during immersion"; else worse during immersion or poor recovery → "Clear waste, then aerate"; else High or Medium risk → "Clean the ghat first"; else "Keep the routine round". The action is never dropped by the word-cap ladder | The officer decides cleaning, aeration and testing (PRD s3), so the brief has to end in an option, not a score. Thin data comes first because a Low-confidence ghat needs a reading before a decision — the same ghats `test_priority` (D-16) lifts. "Clean" describes the ghat, never the water. | Final |
| D-23 | To fit D-18's 150-word cap with the action line, the ladder gained a step (quadrant phrase dropped before the recovery phrase) and the Hindi footer, the Hindi heading and the limit notation (`DO>=5, BOD<=3 mg/l`) were shortened | The recovery wording is the honesty guard (D-15, D-21), so it outranks the quadrant phrase. Durga and Ganesh now both render at detail level 2: readings, quadrant, recovery, confidence and action, inside the cap. | Final |
| D-24 | The `frontend` design branch is adopted as the UI, but every number it shows comes from the API. Its browser-side scoring (`utils/calculations.js`, `utils/confidence.js`, `utils/briefGenerator.js`) and its bundled copy of the readings (`data/bhopal_readings.json`, 710 KB) are deleted; `data/dataService.js` becomes an adapter over `src/api.ts` | Two implementations of the risk score drift, and the claim being judged is that every number traces to one formula and one report page. Scoring stays in `scoring.py`, which has tests. The design is untouched: the adapter renames fields into the shape the components already read. | Final |
| D-25 | The UI reads the API's `risk_level` instead of applying its own thresholds to the score. Labels map High → "High Concern", Medium → "Elevated Risk", Low → "Lower Observed Risk", no level → "Not scored" | The design banded a 0-100 score at 65 / 40 / 20, which contradicts D-12 (0.50 / 0.25). Bairagarh Durga scores 0.527, which is High under D-12 but would have displayed as "Elevated" under the design's rule. One set of bands, in the backend. | Final |
| D-26 | The UI derives exactly two display figures from API values: `duringSeverity` = baseline + immersion damage, and `recoveryDelta` = after severity − baseline severity. Both are marked DERIVED in `dataService.js` and listed in `docs/INTEGRATION.md`. Neither touches a raw reading, and the recovery wording (D-15, D-21) is never replaced by the delta | The API publishes the pre severity and the rise during immersion, not the during severity, and the three-phase card needs it. Arithmetic on two already-computed numbers is traceable; recomputing from readings is not. | Final |
| D-27 | Sites with no readings are not rows in the ranking table. They render in a separate block with the reason, and are never given a rank, a score or a risk colour | The design listed them with `rank: null` and a dash, one row below a ranked ghat, which reads like "least bad". An untested site is not a clean site (PRD s6). | Final |
| D-28 | All fonts are bundled through `@fontsource` (Plus Jakarta Sans, Newsreader, JetBrains Mono, Noto Sans Devanagari); the Google Fonts CDN link is removed from `index.html` | The demo has to render identically on a projector with no network, and the Hindi brief is unreadable without Devanagari present. | Final |
